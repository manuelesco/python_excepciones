Manejo de Excepciones

Qué son y por qué manejarlas

Una excepción es un evento que ocurre durante la ejecución de un programa y que interrumpe el flujo normal de instrucciones. Cuando Python encuentra un error en tiempo de ejecución, crea un objeto de excepción. Si ese objeto no es "atrapado" y manejado, el programa termina mostrando un traceback (un traceback es el reporte que Python genera cuando ocurre una excepción. Muestra la cadena de llamadas realizadas, el archivo, la línea donde ocurrió el problema y el tipo de excepción producida.).

Es importante distinguir entre dos tipos de errores:

  • Errores de sintaxis (SyntaxError): ocurren antes de ejecutar el código, cuando Python no puede interpretar lo que escribiste. Aunque SyntaxError es técnicamente una clase de excepción, no puedes capturarlo con try / except en el mismo archivo donde ocurre, porque el programa ni siquiera llega a ejecutarse.
  • Excepciones: ocurren durante la ejecución, cuando el código es sintácticamente válido pero algo sale mal (dividir entre cero, acceder a un índice inexistente, abrir un archivo que no existe, etc.).

Durante la ejecución de un programa pueden ocurrir situaciones inesperadas que impiden que las instrucciones continúen normalmente. Estas situaciones se conocen como excepciones. Algunas son provocadas por errores de programación, mientras que otras ocurren debido a datos incorrectos introducidos por el usuario, archivos inexistentes, divisiones entre cero, problemas de entrada/salida, entre otros.

El manejo de excepciones es el mecanismo que proporciona Python para detectar y controlar estos eventos de forma ordenada, evitando que el programa termine abruptamente y permitiendo ofrecer mensajes claros al usuario o tomar acciones correctivas.

Sin un manejo adecuado de excepciones, cualquier error durante la ejecución puede detener completamente la aplicación. En cambio, al utilizar las estructuras de control de excepciones, es posible capturar los errores, registrar información relevante, solicitar nuevos datos al usuario o continuar ejecutando otras partes del programa.

Python implementa este mecanismo mediante las palabras reservadas:

  • try: contiene el código que puede generar una excepción.
  • except: captura y procesa una excepción específica o general.
  • else: se ejecuta cuando no ocurre ninguna excepción.
  • finally: se ejecuta siempre, ocurra o no una excepción.
  • raise: permite generar excepciones de manera explícita.

¿Por qué es importante manejar excepciones?

El manejo de excepciones permite:

  • Evitar la terminación inesperada de los programas.
  • Mejorar la robustez y confiabilidad del software.
  • Proporcionar mensajes de error comprensibles para el usuario.
  • Separar la lógica principal del tratamiento de errores.
  • Facilitar la depuración y el mantenimiento del código.
  • Recuperarse de situaciones anómalas cuando sea posible.

Ejemplos de situaciones que pueden generar excepciones

Situación Excepción
Dividir entre cero ZeroDivisionError
Convertir texto a entero inválido ValueError
Acceder a un índice inexistente de una lista IndexError
Abrir un archivo que no existe FileNotFoundError
Utilizar un tipo de dato incorrecto en una operación TypeError
Acceder a un atributo inexistente de un objeto AttributeError

⛳ Objetivo del manejo de excepciones

El objetivo principal no es evitar que ocurran errores, sino detectarlos, controlarlos y responder adecuadamente a ellos, permitiendo que el programa sea más seguro, estable y fácil de utilizar. En aplicaciones reales, el manejo de excepciones es una práctica fundamental para desarrollar software profesional, ya que ayuda a anticipar situaciones inesperadas y garantiza una mejor experiencia para los usuarios.

try / except

Capturando excepciones y accediendo a ellas con as

El bloque try / except es el mecanismo fundamental de Python para anticipar errores, capturarlos y decidir qué hacer con ellos, sin que el programa se detenga abruptamente.

La idea es simple: le dices a Python "intenta ejecutar esto, y si algo sale mal, haz aquello". En lugar de un mensaje de error (traceback) y un programa muerto, obtienes control total sobre la situación.

Sintaxis: 

try:
    # Código que puede lanzar una excepción
    ...
except TipoDeExcepcion:
    # Qué hacer si ocurre ese error
    ...

El flujo es el siguiente:

  1. Python ejecuta el bloque try línea por línea.
  2. Si no ocurre ningún error, el bloque except se ignora por completo.
  3. Si ocurre una excepción, Python detiene el try en ese punto exacto y salta al except correspondiente.
  4. Si la excepción no coincide con ningún except declarado, se propaga hacia arriba y termina siendo un traceback.

💻 Ejemplo

Python ejemplo 
try:
    # Código que puede lanzar una excepción
    resultado = 10 / 0
except ZeroDivisionError:
    # Se ejecuta si ocurre esa excepción específica
    print("Error: no se puede dividir entre cero.")
salida 
Error: no se puede dividir entre cero.

El bloque try "envuelve" el código riesgoso. Si ocurre una excepción del tipo indicado en except, Python salta inmediatamente a ese bloque y continúa desde ahí.

Capturar múltiples excepciones

En la práctica, un mismo bloque de código puede fallar de más de una manera. Imagina que le pides un número al usuario y lo usas para dividir: puede que escriba letras en lugar de un número (ValueError), o que escriba cero (ZeroDivisionError). Son errores distintos, con causas distintas, y lo ideal es manejarlos de forma independiente con mensajes y acciones apropiadas para cada uno.

Python te da dos formas de lograrlo.

Opción 1: Varios bloques except (recomendada)

Cada tipo de error tiene su propio bloque, lo que te permite reaccionar de forma específica ante cada situación.

Sintaxis

try:
    # código riesgoso
    ...
except TipoExcepcion1:
    # manejo específico para el error 1
    ...
except TipoExcepcion2:
    # manejo específico para el error 2
    ...
except TipoExcepcionN:
    # manejo específico para el error N
    ...

💻 Ejemplo

Python ejemplo 
try:
    numero = int(input("Ingresa un número: "))
    resultado = 100 / numero
except ValueError:
    print("Eso no es un número válido.")
except ZeroDivisionError:
    print("No puedes dividir entre cero.")
salida 
# si ingresas cero
No puedes dividir entre cero.

# si ingresas una cadena, por ejemplo: abc
Eso no es un número válido.

# si ingresas un número válido, por ejemplo: 5
(no imprime nada)

Cada bloque maneja un tipo diferente de error, lo que te permite dar mensajes específicos y tomar acciones distintas para cada caso.

Opción 2: Varios tipos en un solo except

Cuando el manejo es idéntico para varios errores, puedes agruparlos en una tupla:

Sintaxis

try:
    # código riesgoso
    ...
except (TipoExcepcion1, TipoExcepcion2, ..., TipoExcepcionN) as e:
    # manejo idéntico para todos los errores
    ...

💻 Ejemplo

Python ejemplo 
try:
    numero = int(input("Ingresa un número: "))
    resultado = 100 / numero
except (ValueError, ZeroDivisionError) as e:
    print(f"Ocurrió un error: {e}")
salida 
# si ingresas cero
Ocurrió un error: division by zero

# si ingresas una cadena, por ejemplo: a
Ocurrió un error: invalid literal for int() with base 10: 'a'

Útil cuando el manejo es idéntico para ambos errores.

Acceder al objeto de excepción con as

Cuando ocurre una excepción, Python no solo interrumpe el flujo, sino que crea un objeto que contiene información detallada sobre el error. Por defecto, al capturar una excepción con except, ese objeto existe pero lo estás ignorando. Con la palabra clave as (que ya apareció en la opción 2) puedes darle un nombre y acceder a él para obtener detalles útiles como el mensaje, el tipo o los argumentos del error.

Esto es especialmente valioso cuando quieres mostrar mensajes de error descriptivos, registrar el error en un log, o tomar decisiones distintas según el contenido específico del error, no solo su tipo.

Sintaxis

try:
    # código riesgoso
    ...
except TipoDeExcepcion as e:
    print(e)            # mensaje legible del error
    print(type(e))      # clase exacta de la excepción
    print(e.args)       # tupla con los argumentos del error

La variable e es simplemente el nombre convencional — puedes llamarla como quieras, aunque e, ex o err son los más usados por la comunidad.

💻 Ejemplo

Python ejemplo 
try:
    lista = [1, 2, 3]
    print(lista[10])
except IndexError as e:
    print(f"Tipo de error: {type(e).__name__}")
    print(f"Mensaje: {e}")
    print(f"Argumentos: {e.args}")
salida 
Tipo de error: IndexError
Mensaje: list index out of range
Argumentos: ('list index out of range',)
📝 Nota:

El alcance de e está limitado al bloque except: al salir de él, Python elimina la variable y usarla provocaría un NameError.

⚠️ Precaución:

Evita usar except: (sin tipo) o except Exception: como única cláusula sin relanzar o registrar el error. Esto "traga" silenciosamente cualquier fallo, incluyendo bugs reales en tu código, haciendo la depuración extremadamente difícil. Además, except: sin tipo captura también KeyboardInterrupt y SystemExit (por ejemplo, Ctrl+C dejaría de detener tu programa), mientras que except Exception: no los captura.

⚠️ Precaución:

Ten cuidado con el orden de los bloques except cuando capturas excepciones de una jerarquía. Siempre coloca las más específicas antes que las más generales. Si pones except Exception antes que except ValueError, el ValueError nunca será alcanzado porque Exception lo captura primero. Lo mismo ocurre con FileNotFoundError, que es subclase de OSError: si capturas OSError antes, el except FileNotFoundError nunca se ejecutará.

✅

else

Código que depende del éxito del try

Se ejecuta solo si no ocurrió ninguna excepción en el bloque try. Es la forma correcta de separar "el código que puede fallar" de "el código que depende de que no haya fallado":

Sintaxis

try:
    # código riesgoso
    ...
except TipoDeExcepcion:
    # se ejecuta si ocurrió el error
    ...
else:
    # se ejecuta SOLO si no ocurrió ninguna excepción
    ...

💻 Ejemplo

Python ejemplo 
try:
    archivo = open("datos.txt", "r")
except FileNotFoundError:
    print("El archivo no existe.")
else:
    contenido = archivo.read()
    print(f"Archivo leído: {len(contenido)} caracteres.")
    archivo.close()
salida 
# si datos.txt no existe
El archivo no existe.

# si datos.txt existe y tiene 10 caracteres
Archivo leído: 10 caracteres.

Observa que la lectura del archivo está en else y no dentro de try: el try solo contiene la línea que realmente puede lanzar FileNotFoundError.

💡 Tip:

Usa else para mantener el bloque try lo más pequeño posible. Solo debe contener el código que realmente puede lanzar la excepción que quieres capturar. El código que depende del éxito va en else.

⚠️ Precaución:

Una excepción lanzada dentro de else no es capturada por los except del mismo try: sube hacia el código exterior. Lo mismo ocurre con las excepciones lanzadas dentro de finally.

♻️

finally

Limpieza que se ejecuta siempre

Se ejecuta siempre, haya o no habido excepción, e incluso si hay un return dentro del try. Es ideal para liberar recursos: 

try:
    # código riesgoso
    ...
except TipoDeExcepcion:
    # se ejecuta si ocurrió el error
    ...
finally:
    # se ejecuta SIEMPRE, haya o no excepción
    ...

💻 Ejemplo

Python ejemplo 
archivo = None
try:
    archivo = open("datos.txt", "r")
    datos = archivo.read()
    int(datos)  # lanza ValueError si el contenido no es un número
except ValueError:
    print("El archivo no contiene un número válido.")
except FileNotFoundError:
    print("No se encontró el archivo.")
finally:
    if archivo is not None:
        archivo.close()
    print("Bloque finally ejecutado siempre.")
salida 
# si datos.txt no existe
No se encontró el archivo.
Bloque finally ejecutado siempre.

# si datos.txt contiene: abc
El archivo no contiene un número válido.
Bloque finally ejecutado siempre.

# si datos.txt contiene: 42
Bloque finally ejecutado siempre.

El mensaje del finally aparece en los tres casos, y es ahí donde se cierra el archivo (si llegó a abrirse).

Alternativa moderna: with

Para liberar recursos como archivos, la práctica moderna es el gestor de contexto with, que cierra el recurso automáticamente al salir del bloque, haya o no excepción. Estos dos fragmentos cierran el archivo de forma equivalente: 

archivo = None
try:
    archivo = open("datos.txt", "r")
    contenido = archivo.read()
finally:
    if archivo is not None:
        archivo.close()

with open("datos.txt", "r") as archivo:
    contenido = archivo.read()

with solo garantiza la liberación del recurso; no captura la excepción. Si quieres manejarla, sigues necesitando un try / except alrededor.

raise

Lanzar y encadenar excepciones

🚀 Lanzar excepciones con raise

Hasta ahora hemos visto cómo capturar excepciones que Python lanza automáticamente cuando algo sale mal. Pero a veces eres tú quien necesita lanzarlas manualmente, porque tu código detectó una condición inválida que Python por sí solo no consideraría un error.

Por ejemplo, Python no tiene problema en aceptar una edad negativa como número entero válido, pero para tu aplicación eso es un error. raise te permite establecer tus propias reglas y comunicarlas mediante excepciones, usando el mismo mecanismo que usa Python internamente.

⚙️ Sintaxis básica

Lanzar una excepción de forma explícita: 

raise TipoDeExcepcion("mensaje de error personalizado")

💻 Ejemplo:

Python ejemplo 
edad = -5

if edad < 0:
    raise ValueError("La edad no puede ser negativa")
salida 
Traceback (most recent call last):
  File "ejemplo.py", line 4, in <module>
    raise ValueError("La edad no puede ser negativa")
ValueError: La edad no puede ser negativa

Qué está pasando

  1. La condición edad < 0 se cumple, porque edad vale -5.
  2. raise ValueError(...) crea la excepción y detiene el flujo normal del programa en ese punto.
  3. No hay ningún try / except que la capture, así que la excepción llega hasta el intérprete de Python, que termina el programa y muestra el traceback.
  4. El traceback indica, de arriba hacia abajo, el archivo y la línea donde se lanzó la excepción (line 4), el código de esa línea y, en la última línea, el tipo de excepción con su mensaje.
💡 Tip:

Para capturar la excepción y evitar que el programa se detenga abruptamente, debes envolver el bloque donde se evalúa y se lanza (raise) el error dentro de un bloque try, y manejar el error en la sección except. 

edad = -5

try:
    if edad < 0:
        raise ValueError("La edad no puede ser negativa")
except ValueError as e:
    print(f"Excepción capturada: {e}")

print("El programa continúa su ejecución normal...")

👍 Validar entradas de funciones

Es muy común usar raise para asegurarte de que los argumentos pasados a una función cumplen con los requisitos mínimos antes de continuar la ejecución.

💻 Ejemplo:

Python ejemplo 
def verificar_edad(edad):
    if edad < 0:
        raise ValueError("La edad no puede ser un número negativo.")
    elif edad < 18:
        print("Acceso denegado: eres menor de edad.")
    else:
        print("Acceso concedido.")

# Uso:
verificar_edad(-5)
salida 
Traceback (most recent call last):
  File "ejemplo.py", line 10, in <module>
    verificar_edad(-5)
  File "ejemplo.py", line 3, in verificar_edad
    raise ValueError("La edad no puede ser un número negativo.")
ValueError: La edad no puede ser un número negativo.

Qué está pasando

  1. Se llama a verificar_edad(-5) y la función recibe edad = -5.
  2. La primera condición, edad < 0, se cumple y se ejecuta raise ValueError(...).
  3. El raise sale de la función de inmediato: no se evalúan el elif ni el else, por eso no se imprime "Acceso denegado" ni "Acceso concedido".
  4. Como no hay un try / except que la capture, el programa termina con un traceback de dos niveles: primero la línea que llamó a la función (line 10) y después la línea del raise dentro de ella (line 3).
  5. Con una edad válida no se lanza ninguna excepción: verificar_edad(25) imprime Acceso concedido. y verificar_edad(15) imprime Acceso denegado: eres menor de edad.

🔁 Relanzar una excepción: raise sin argumentos (re-raise)

A veces quieres capturar una excepción con try-except para registrar el error (en un archivo de log, por ejemplo) o realizar alguna limpieza, pero aun así deseas que el error se propague hacia afuera. En este caso, usas raise solo, sin argumentos.

Para recibir la excepción relanzada con raise, debes envolver la llamada al primer bloque (o a la función que contiene dicho bloque) dentro de otro bloque try/except externo.

💻 Ejemplo:

Python ejemplo 
def realizar_division():
	# --- Nivel inferior ---
    try:
        resultado = 10 / 0
    except ZeroDivisionError:
        print("[Nivel Interno] Registrando el error...")
        raise  # Relanza la excepción hacia quien llamó a la función


# --- Nivel superior ---
try:
    realizar_division()
except ZeroDivisionError:
    print("[Nivel Externo] Excepción capturada con éxito. El programa continúa sin colapsar.")

print("Fin de la ejecución.")
salida 
[Nivel Interno] Registrando el error...
[Nivel Externo] Excepción capturada con éxito. El programa continúa sin colapsar.
Fin de la ejecución.

Qué está pasando

  1. El bloque interno (dentro de la función) detecta la división entre cero y cae en su propio except.
  2. Imprime "[Interno] Registrando el error...".
  3. La sentencia raise interrumpe el bloque interno y manda el ZeroDivisionError hacia "arriba".
  4. El bloque try externo atrapa la excepción relanzada.
  5. Se ejecuta el except ZeroDivisionError externo y el programa continúa su ejecución normal sin interrumpir el script.

⛓️ Encadenar excepciones: raise ... from ...

Puedes transformar una excepción de bajo nivel en una más comprensible o relevante para tu aplicación sin perder el contexto original.

Sintaxis

raise NuevaExcepcion("mensaje") from excepcion_original

💻 Ejemplo:

Python ejemplo 
def leer_edad(texto):
    try:
        return int(texto)
    except ValueError as e:
        raise ValueError(f"Edad inválida: {texto!r}. Debe ser un número entero.") from e

try:
    leer_edad("veinte")
except ValueError as err:
    print(f"Error: {err}")
    print(f"Causa original: {err.__cause__}")
salida 
Error: Edad inválida: 'veinte'. Debe ser un número entero.
Causa original: invalid literal for int() with base 10: 'veinte'

Qué está pasando

  1. int("veinte") falla y lanza un ValueError.
  2. Lo capturamos y lanzamos una excepción nueva (otro ValueError) con un mensaje más claro para quien use la función, que incluye el valor recibido.
  3. Con from e, la excepción original queda guardada en el atributo __cause__ de la nueva.
📝 Nota:

Si lanzas una excepción dentro de un except sin usar from, Python también enlaza ambas excepciones, pero de forma implícita (en __context__). Con from e la relación queda explícita en __cause__.

🤫 Suprimir la causa: from None

Si no quieres que el traceback muestre la excepción original, usa from None. Esto deja __cause__ en None y evita que el traceback muestre la excepción anterior, aunque esta sigue disponible en el atributo __context__.

Python ejemplo 
def leer_edad(texto):
    try:
        return int(texto)
    except ValueError:
        raise ValueError(f"Edad inválida: {texto!r}. Debe ser un número entero.") from None

try:
    leer_edad("veinte")
except ValueError as err:
    print(f"Error: {err}")
    print(f"Causa: {err.__cause__}")
salida 
Error: Edad inválida: 'veinte'. Debe ser un número entero.
Causa: None

Si esta excepción no se capturara, el traceback mostraría únicamente la nueva excepción, sin la de int().
